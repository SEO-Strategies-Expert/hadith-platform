# تطبيق الجوال — الكلّية العليا للحديث النبوي وعلومه وعِلَله

تطبيق iOS و Android مبنيّ على **Expo SDK 57** و **React Native 0.86** و **expo-router**،
يستهلك واجهة `‎/api/v1` الموثّقة في عقد الخادم.

---

## ⚠️ تنبيه لازم قبل أوّل دفعٍ إلى المستودع

**وجود مجلّد `mobile/` يكسر بناء Next.js على Vercel ما لم يُستثنَ من `tsconfig.json` الجذر.**

السبب: `tsconfig.json` في جذر المستودع يجمع كل ملفّات المشروع:

```json
"include": ["next-env.d.ts", "**/*.ts", "**/*.tsx", ".next/types/**/*.ts", ".next/dev/types/**/*.ts", "**/*.mts"],
"exclude": ["node_modules"]
```

فتدخل ملفّات `mobile/**` في فحص أنواع `next build`. وبما أنّ `mobile/node_modules`
لا يُرفع إلى Vercel (مستثنى في `.gitignore`)، تفشل استيراداتُها جميعًا.

تُقيس ذلك تجربةٌ محاكية لبيئة Vercel (مصدر `mobile/` موجود واعتماديّاته غائبة):

```
76 خطأ TS2307: Cannot find module 'react-native' / 'expo-router' / …
```

كما أنّ وجود `mobile/node_modules` محلّيًّا يُدخل نسخةً ثانية من `@types/node`
تُعيد تعريف `FormData` عالميًّا، فيظهر خطآن في `src/app/api/admin/upload/route.ts`
و`src/app/api/forms/[kind]/route.ts` لا علاقة لهما بشيفرة الموقع.

### الإصلاح — سطر واحد في `tsconfig.json` الجذر

```diff
- "exclude": ["node_modules"]
+ "exclude": ["node_modules", "mobile"]
```

هذا السطر يزيل الخطأين المذكورين والأخطاء الستّة والسبعين معًا، ولا يمسّ شيفرة
الموقع بحال. **لم يُطبَّق في هذا العمل لأنّ نطاق العمل يقتصر على `mobile/`.**

بديلٌ مكافئ: إنشاء `.vercelignore` في الجذر يحوي سطر `mobile`.

## التشغيل محلّيًّا

### المتطلّبات
- Node.js 20 فأعلى (اختُبر على 24).
- تطبيق **Expo Go** على الهاتف، أو محاكي Android/iOS.

### الخطوات

```bash
cd mobile
npm install
cp .env.example .env      # ثمّ اضبط عنوان الخادم
npx expo start
```

ثمّ امسح رمز QR بتطبيق Expo Go، أو اضغط `w` لفتح نسخة الويب.

للتحقّق من الأنواع:

```bash
npm run typecheck        # tsc --noEmit — يجب أن يكون صفر أخطاء
```

## ضبط عنوان الخادم

عنوان الخادم **في موضع واحد فقط**: متغيّر البيئة `EXPO_PUBLIC_API_URL`،
يقرأه `app.config.ts` ويضعه في `extra.apiBaseUrl`، ويقرأه من هناك `src/config.ts`
وحده. **لا يوجد رابط مكتوب داخل أيّ شاشة.**

ملفّ `.env`:

```bash
# خادم محلّي (محاكي أو ويب)
EXPO_PUBLIC_API_URL=http://localhost:3000

# جهاز حقيقي على الشبكة نفسها — ضع عنوان الحاسوب لا localhost
# EXPO_PUBLIC_API_URL=http://192.168.1.10:3000

# إنتاج
# EXPO_PUBLIC_API_URL=https://hadith-platform-hassan67844-4138s-projects.vercel.app

EXPO_PUBLIC_WEBSITE_URL=https://hadith-platform-hassan67844-4138s-projects.vercel.app

# يلزم لإشعارات Push — يُملأ بعد `eas init`
# EXPO_PUBLIC_EAS_PROJECT_ID=…
```

> على جهاز حقيقي لا يعمل `localhost` لأنّه يشير إلى الهاتف نفسه.

## قرارات تقنيّة تُذكر

### تدوير رموز التجديد
رمز التجديد **يُدوَّر**: كل تجديد يُبطل القديم، واستعمال رمزٍ مُبطَل يُبطل **كل**
جلسات المستخدم على كل أجهزته. لذلك في `src/api/client.ts`:

- التجديد **مسلسل بوعدٍ واحد مشترك** (`refreshShared`) — لا يقع تجديدان متوازيان أبدًا.
- الرمز الجديد يُحفظ **فورًا** قبل إعادة أيّ طلب.
- طلبٌ فشل بـ401 بينما جُدِّد الرمز أثناء رحلته يُعاد **بالرمز الجديد بلا تجديد ثانٍ**.
- فشل التجديد بـ401 ⇒ مسح الرموز والعودة إلى شاشة الدخول.

### تخزين الرموز
`expo-secure-store` على iOS و Android (سلسلة المفاتيح / Keystore) — لا `AsyncStorage`.

> **الويب**: `expo-secure-store` غير مدعوم في المتصفّح، فتسقط النسخة إلى
> `sessionStorage`. **نسخة الويب للتطوير والمعاينة فقط ولا تُنشر للطلّاب.**

### الاتّجاه واللغة
العربيّة هي الافتراض دائمًا (لا تُشتقّ من لغة الجهاز)، والاتّجاه RTL مثبَّت على
مستوى النظام بإضافة `expo-localization` (`forcesRTL: true`). الأرقام في الواجهة
العربيّة هنديّة (٠١٢٣٤٥٦٧٨٩) اتّساقًا مع الموقع. اختيار الإنجليزيّة من شاشة
الإعدادات يغيّر النصوص ويُبقي الاتّجاه RTL.

### الاختبارات
أسئلة الاختبار لا تصل من الخادم إلّا مع محاولة مفتوحة، فتُؤدَّى المحاولة في شاشة
الاختبار نفسها. **الإجابات تبقى في ذاكرة الشاشة ولا تُكتب في أيّ تخزين محلّي.**
المؤقّت عرضٌ فقط، والحكم النهائي على الوقت لساعة الخادم، والتسليم يُرسل دائمًا
حتّى لو بدا الوقت منقضيًا.

## البناء للمتجرين (EAS Build)

### تهيئة لمرّة واحدة

```bash
npm install -g eas-cli
eas login                 # بحساب Expo الخاصّ بالكلّية
cd mobile
eas init                  # ينشئ المشروع ويعطي projectId
eas build:configure       # ينشئ eas.json
```

ضع `projectId` الناتج في `.env` تحت `EXPO_PUBLIC_EAS_PROJECT_ID` — **بدونه لا
تعمل إشعارات Push** (لا يمكن استخراج رمز Expo).

### معرّفات الحزمة

في `app.config.ts` معرّفان مبدئيّان يجب أن يوافقا ما يُسجَّل في حسابَي المتجرين:

```ts
ios:     { bundleIdentifier: 'com.hadithcollege.app' }
android: { package: 'com.hadithcollege.app' }
```

### البناء

```bash
eas build --platform android --profile production
eas build --platform ios --profile production
```

### الرفع

```bash
eas submit --platform android --latest
eas submit --platform ios --latest
```

## نواقص معلومة في الخادم (لا تُعالَج من التطبيق)

### ١) مسارات `auth/*` بلا ترويسات CORS
`‎/api/v1/auth/{login,refresh,logout}` هي **المسارات الوحيدة** في `‎/api/v1` التي
لا تُصدِر ترويسات CORS ولا تُصدِّر `OPTIONS`؛ بقيّة المسارات تفعل.

الأثر:
- **التطبيق الأصيل (iOS/Android): لا أثر إطلاقًا** — لا `Origin` ولا سياسة أصل.
- **نسخة الويب: الدخول متعذّر** — يُحجب الردّ في المتصفّح رغم أنّ الخادم يعيد `200`.

الإصلاح في الخادم: تمرير مسارات `auth/*` على مساعد CORS نفسه الذي تستعمله بقيّة
المسارات، وتصدير `OPTIONS` منها.

### ٢) `MOBILE_WEB_ORIGINS` غير مضبوط
لازم في Vercel قبل نشر نسخة ويب. في غير الإنتاج تُضاف `localhost:8081` تلقائيًّا
(وقد تحقّقنا أنّها تعمل على `‎/me` و`‎/me/courses`).

### ٣) صيغ `href` في الإشعارات غير موثّقة
العقد يقول «حوّله لمسار التطبيق المقابل» دون تعداد صيغ مسارات الموقع.
المحوّل في `src/notifications/hrefMap.ts` مبنيّ على التقاط المعرّف بعد الكلمة
الدالّة (`course`, `lesson`, `quiz`, `assignment`, …)، وما لا يُطابَق يُترك بلا
انتقال. يُراجَع عند توثيق الصيغ الفعليّة.
